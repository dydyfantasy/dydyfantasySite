## Recommandations priorisées

### 1. Pré-rendre chaque route (impact : fort) — objet de l'étape 2
- **Mécanisme** : Googlebot indexe en deux temps ; le rendu JS passe par une file d'attente, ce qui retarde ou appauvrit la prise en compte. Aujourd'hui, la première lecture voit 6 URL avec le même title, la même description, 0 mot et 0 lien, et les autres moteurs ou réseaux sociaux qui n'exécutent pas le JS (Bing en partie, aperçus Facebook/WhatsApp) ne voient jamais le contenu. Un HTML pré-rendu par route expose title, meta, canonical, H1, texte, liens et JSON-LD dès la première lecture.
- **Vérification** : après build, `build/client/<route>/index.html` existe pour chaque route ; `curl -s https://dydyfantasy.fr/contact | grep -c "<h1"` = 1 ; Search Console > Inspection de l'URL > « Afficher la page explorée » montre le texte.

### 2. 301 `/notre-approche` → `/mon-approche` et vrai 404 (impact : fort)
- **Mécanisme** : `/notre-approche` a encore 290 impressions ; en 200 vide, c'est un doublon faible qui ne transmet pas ses signaux. Une 301 les consolide sur `/mon-approche`. Les URL inconnues en 200 sont des soft 404 qui gaspillent l'exploration et peuvent être indexées.
- **Vérification** : `curl -sI https://dydyfantasy.fr/notre-approche` → `301` + `Location: https://dydyfantasy.fr/mon-approche` ; `curl -sI https://dydyfantasy.fr/xyz` → `404` ; rapport GSC « Pages » sans « Soft 404 ».

### 3. Un seul JSON-LD `LocalBusiness` cohérent (impact : moyen)
- **Mécanisme** : Google rapproche les données structurées de l'entité (fiche locale, Knowledge Graph). Deux blocs contradictoires (image, `sameAs`, adresse, téléphone) brouillent ce rapprochement. Un bloc unique avec `@id`, `telephone`, `areaServed` réel (Haute-Garonne, Gers, Tarn, communes de l'ouest toulousain) et `sameAs` normalisés le renforce, et peut aider sur les requêtes « gers ».
- **Vérification** : Test des résultats enrichis / validator.schema.org sur chaque URL ; un seul `LocalBusiness` détecté, sans avertissement.

### 4. Pages de l'architecture cible alignées sur les requêtes (impact : fort, plus long terme)
- **Mécanisme** : une page se classe sur une intention si elle la traite explicitement (title, H1, contenu). Aucune page ne cible aujourd'hui DJ, mariage, anniversaire, team building ni le Gers, d'où des positions 13-30 obtenues uniquement par la home. Prioriser : DJ (dj gers 179 imp.), Anniversaire (+ Gers), Team building / entreprise (séminaire, soirée d'entreprise), Blind Test & Quiz, Mariage. L'animation micro / speaker (Decathlon, 117 imp.) mérite une section identifiable, en citant uniquement des références réelles.
- **Vérification** : après indexation, GSC > Performances, filtre par page : impressions et position sur ces requêtes ; ajouter chaque nouvelle route au sitemap.

### 5. Titles, descriptions et Open Graph par page (impact : moyen)
- **Mécanisme** : le title est un signal de pertinence et, avec la description, détermine le CTR (`/prestations` : 342 imp., CTR 0,3 %). Au-delà de ≈ 60 car. / 160 car., Google tronque ou réécrit. `og:image` absent = aperçus sans image sur WhatsApp/Facebook (canaux de prise de contact).
- **Vérification** : longueurs mesurées dans le HTML pré-rendu ; débogueur de partage Facebook ; CTR par page dans GSC 4 à 8 semaines après.

### 6. Slash final et `/privacy` (impact : faible)
- **Mécanisme** : `/contact/` en 200 crée un doublon (atténué par le canonical, mais seulement après JS). `/privacy` concerne l'application Dydy Quiz et est indexable (title « Dydy Quiz ») : contenu hors sujet pour la marque. Une 301 sans slash et un `noindex` (ou un title explicite) évitent ces signaux parasites.
- **Vérification** : `curl -sI https://dydyfantasy.fr/contact/` → 301 ; balise `noindex` visible dans le HTML brut de `/privacy`.

### 7. Déploiement
- La production sert un bundle plus ancien que le `dist/` audité : les gains ne seront mesurables qu'après mise en ligne. Noter la date de déploiement pour comparer les données Search Console avant/après.
